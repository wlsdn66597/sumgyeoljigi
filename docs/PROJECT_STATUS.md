# NUNI(숨결지기) 진행 상황 · 남은 작업 · 분업

기준일 2026-10-19. 근거 문서는 개발계획서, 대회 스마트가전 부문 세부 안내사항 v6, LG 가이드 문서(guide-documents 23종: 개요·개발환경·D-Bus·앱/서비스 생명주기·appinfo/serviceinfo·ARC/Flutter CLI·ECO.AI·샘플·WiFi), 그리고 이 저장소의 작업 기록이다. 가전 API(ThinQ) 연동은 이번 계획에서 뺐다.

## 1. 대회 요건 (문서 확인 결과)

| 항목 | 내용 | 우리에게 주는 의미 |
|---|---|---|
| 결선 서류 | **10월** 제출: 개발완료보고서(PPT 20쪽 이내, PDF), 작품소개서(2쪽), 시연 동영상(3분 이내, 720p, YouTube), 소스코드(GitHub `2026ESWContest_smart_팀명`). 11월 오프라인 발표·시연 | **정확한 마감일을 홈페이지에서 확인해 일정을 역산한다** |

| 플랫폼 | LG 플랫폼(atlas)이 Pi 4·Pi Zero에 탑재되어 제공. 그 밖의 추가 장비는 플랫폼 제한 없음. 결과물은 LG 플랫폼에서 하나 이상의 서비스로 동작 | 추가 파이는 일반 리눅스 + Python으로 써도 된다 |
| 개발 언어 | 플랫폼 앱: Flutter·React 등 / 플랫폼 서비스: Node.js 등 / 그 밖: 제한 없음 | 제출용 대시보드는 Flutter |
| 결선 배점 | 완성도 60(계획서 기술의 구현 정도 포함), 독창성 20, 활용성 20 | 계획서와 달라진 점은 보고서 '장애요인과 해결'에서 설명 |
| 가산점 | ① LG 플랫폼 기반 ESP32·Pi 4·Pi Zero 3종 연동 +5 ② 멀티모달 센서 융합 +5 | 둘 다 노린다. ①은 Pi Zero 연결이 조건 |
| 제공 장비 | 7인치 HDMI 터치 디스플레이 1~2대, 카메라, ESP32 CAM, 아두이노·ESP32·ESP8266 | 화면은 제공된 7인치를 우선 쓴다 |

| 프로파일 | 대회는 Headless(화면 없음)·Video(화면 + 영상) 사용 | 화면 앱은 화면 있는 프로파일 기기에 올린다 |
| 플랫폼 상태 | 개발 단계. 기기 간 연동(Connectivity)은 개발 예정 | 가전 연동은 직접 구현 |

## 2. 현재까지 완료된 작업

| 영역 | 상태 | 내용 |
|---|---|---|
| 레이더 호흡 | ✅ 실측 | MR60BHA2(XIAO ESP32-C6, ESPHome)로 호흡·심박·거리·재실·움직임. 무호흡 규칙, 서보 호흡 시뮬레이터(정답 기준). 호흡값 게이팅·스무딩으로 요동·무호흡 오탐 수정 |
| 환경 센서 | ✅ 실측 | SCD41(CO₂·온습도, I2C). 조도는 임시값 |
| 울음 감지 | ✅ 실시간 | YAMNet(TFLite) 내장 울음 점수, 가정 원거리 감지율 97% |
| 소리 종류 | ✅ | 울음·칭얼거림·웃음·기침 Macro-F1 0.83 (무학습) |
| 울음 원인 힌트 | ✅ 모듈 / ❌ 파이 미연결 | `cry_personal.py`: 아기별로 학습하는 1·2순위 행동 힌트(수유 / 기저귀 / 안아주기), 자가 검증. 가상 세계 1순위 0.61, 2순위 안 0.88(무작위 0.33 / 0.67). 상세는 `docs/CRY_SIMULATION.md` |
| 융합·알림 | ✅ | 멀티모달 위험도 판단, 디바운스·쿨다운. 실물에서 '울음 + 호흡 이상' 교차검증 성공 |
| 파이 상시 실행 | ✅ | Mosquitto, nuni-edge, Streamlit 대시보드(:8501), 기록기, SCD41, 레이더 브리지(systemd) |
| 대시보드 | ⚠️ 임시 | Streamlit. 제출용 Flutter는 아직 |
| 음성 | ⚠️ 일부 | 제한된 인텐트만. STT·스피커 응답 남음 |
| 가전 제어 | ❌ | 권고 로직만 있고 실물 구동 없음 |
| atlas 이식 | ⚠️ 환경만 | WSL2·Docker·ARC CLI 개발환경 구축, 샘플 서비스를 IPK로 빌드해 기기 설치·D-Bus 호출·재부팅 후 동작까지 검증. 배포 함정 5가지 정리(오프라인 루트 경로, read-only 루트, D-Bus 파일 권한, UID 불일치, systemd 유닛 위임). 우리 서비스는 아직 |
| Pi Zero | ❌ | 미사용 |

## 3. 남은 작업

### A. 필수 요건·제출
1. 결선 서류 마감일 확인
2. atlas 최소 서비스: Pi 4에 C++ 네이티브 서비스(ECO.AI로 YAMNet 울음 감지, 센서 수신, D-Bus 발행, systemd 유닛 위임). 기기에서 mosquitto·ECO.AI 애드온·PulseAudio 마이크 접근 확인
3. Pi Zero 연결(머리맡 알림 노드) — 필수 장비이자 가산점 ① 조건
4. GitHub 저장소 정리: 이름 규칙, 민감정보(WiFi 비밀번호·토큰) 제거 확인(수상 시 공개)

### B. 하드웨어·기능 확장
| 작업 | 할 일 | 주의 |
|---|---|---|
| 진동 모듈 | Pi Zero 또는 ESP32 GPIO(드라이버 모듈 경유)로 울음·무호흡 경보 진동 | 아기 침대 근처면 레이더 측정 간섭 가능 → 간섭 테스트 필수 |
| ToF 센서 | VL53L1X(I2C)로 부모 접근·아기 위치 감지, 레이더 재실 교차검증 | 설치 위치·시야각 |
| MR60 확인 → WiFi CSI | ① 서보로 장시간 측정해 끊김 빈도·호흡 오차 기록 ② 끊김이 잦으면 ESP32 두 대로 CSI 수집 → 호흡 대역 추출 → 서보로 검증 | CSI는 보조 센서로. 기한 넘기면 접는다 |
| 화면 | 7인치 디스플레이에 대시보드: 당장 Streamlit 전체화면, 제출용 Flutter | atlas 화면 앱은 화면 있는 프로파일 기기에서만 |
| 파이 두 대 분리 | atlas Pi 4 = 필수 플랫폼 서비스 / 일반 파이 = Python(울음 힌트, 리포트, 기록, 보조 융합), MQTT 연결 | 공유 Debian 파이는 시스템 변경 전 사전 합의 |
| USB 가습기 | ESP32 + 릴레이(또는 MOSFET)로 5V 전원 제어, '습도 낮음 → 자동 가습' 시연 | 상태 회신 토픽 포함 |

### C. 울음
1. 파이 연결: yamnet_cry가 임베딩·1초 소리를 넘기도록 → 울음 구간 추적 → 10초에 힌트 발행 → '무엇으로 그쳤나요?' 답 받기, 변환 파일 3종 복사
2. 파이에서 처리 시간 측정(노트북 1초 창당 18ms)
3. 시뮬레이션 마무리: 자가 검증 시연 설정 결정, 새 기본값 긴 기간 시험(GPU 서버 필요), 학습 곡선 그림
4. 보고서 문구: '울음 의도 분류' → '아기별로 학습하는 1·2순위 힌트', 가상 검증 기준과 무작위 기준선 병기

### D. 기타
- 실측 정량표: 호흡 오차, 무호흡 감지 지연, 울음 혼동표, E2E 지연, 야간 오경보
- 조도 센서(가산점 ②), 음성 STT·스피커(VoiceManager1 한국어 확인 또는 Vosk)
- GPU 서버(aix408-24) 10-17부터 오프라인 → 복구 확인

## 4. 분업 (2인)

### 0일차: 같이 정할 것
1. 결선 마감일 확인, 일정 역산
2. **메시지 규격 확정** — 이후 둘이 서로 기다리지 않는 핵심

| 토픽 | 보내는 쪽 → 받는 쪽 | 내용 |
|---|---|---|
| `sensor/radar` (기존) | MR60 → 융합 | 호흡·심박·거리·재실 |
| `sensor/tof` | ESP32 → 융합 | 거리(mm), 사람 있음 |
| `sensor/csi` | ESP32 → 융합 | CSI 호흡수, 신뢰도 |
| `cry/hint`, `cry/feedback` | 울음 모듈 ↔ 화면 | 1·2순위 힌트, 부모 답 |
| `actuator/humidifier` | 융합 → ESP32 | on/off, 이유 (+상태 회신) |
| `actuator/vibration` | 융합 → Pi Zero | 패턴, 세기 |
| `fusion/state` (기존) | 융합 → 화면·알림 | 위험도, 이유 |

3. 장비 배정: atlas Pi 4 = B 전담, Pi Zero·ESP32·부품 = A 전담, 일반 파이 = B
4. 부품 주문: 진동 모듈, VL53L1X, 릴레이/MOSFET, USB 가습기, CSI용 ESP32

### 담당 A — 하드웨어·센서 (김진우)
| 순서 | 작업 | 혼자 진행 가능한 이유 |
|---|---|---|
| 1 | MR60 장시간 측정(끊김·호흡 오차) | 지금 장비로 바로 가능, 정량표 확보 |
| 2 | USB 가습기 ESP32 + 릴레이 제어 | MQTT 명령은 손으로 발행해 시험 |
| 3 | Pi Zero 머리맡 노드 + 진동 모듈 | 입력은 가짜 MQTT로 시험 |
| 4 | ToF 센서(ESP32, `sensor/tof`) | 독립 |
| 5 | 진동-레이더 간섭 테스트 | 3번 이후 |
| 6 | (끊김이 잦으면) WiFi CSI 호흡 | 보조라 늦어도 다른 일을 막지 않음 |
| 7 | 조도 센서(여유 시) | 독립 |

Pi Zero에 atlas 서비스를 올릴 때는 B가 정리한 배포 템플릿을 받아 쓴다.

### 담당 B — 플랫폼·AI (장수인)
| 순서 | 작업 | 혼자 진행 가능한 이유 |
|---|---|---|
| 1 | atlas 최소 서비스(C++, ECO.AI YAMNet, D-Bus) | 필수 요건, 센서는 가짜 MQTT로 대체 |
| 2 | 배포 템플릿 정리 → A에게 전달 | Pi Zero 병목 해소 |

| 6 | 울음 시뮬레이션 마무리 | 독립 |
| 7 | 융합에 ToF·CSI·가습기 상태 반영 | 0일차 규격대로 짜 두면 실물이 붙는 순간 동작 |
