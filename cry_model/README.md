# 울음 분류 (YAMNet 전이학습)

**2단계 설계**
1. **울음 감지(is_crying)**: YAMNet에 내장된 AudioSet `Baby cry, infant cry` 점수를 그대로 쓴다. 별도 학습은 필요 없고, 실시간 경로는 `yamnet_cry.py`(tflite)다.
2. **울음 이유 3클래스 분류(실험적)**: YAMNet 세그먼트 임베딩(1024-d)을 커스텀 헤드에 넣는다.
   - `hungry` 배고픔
   - `sleepy` 졸림·피곤
   - `discomfort` 신체 불편: 복통, 트림 필요(가스), 일반 불편, 덥거나 추움

   `lonely`/`scared`(정서), `unknown`, 웃음·소음 같은 비울음은 학습에서 뺀다. 매핑은 `config.LABEL_MAP` 한 곳에서 관리한다.

## 설치

```bash
pip install -r requirements-ml.txt      # Python 3.9~3.11
```
Donate-a-Cry 원본 버킷(.3gp/.caf)을 쓰려면 ffmpeg가 필요하다. PATH에 두거나 `NUNI_FFMPEG`로 경로를 지정한다.

## 데이터

원본 데이터는 용량과 라이선스 때문에 저장소 밖에 둔다. `NUNI_CRY_DATA` 기본값은 `cry_model/data`다.

```bash
export NUNI_CRY_DATA=D:/datasets/cry
python download_data.py all     # Donate-a-Cry · ESC-50 · OpenSLR 28
python prepare_data.py          # → manifest.csv (출처·라벨·아기 group·중복 제거)
python check_env.py
```

| 출처 | 용도 | 라이선스 |
|---|---|---|
| Donate-a-Cry 정제본 457개 + 원본 버킷(정제본에 없는 녹음) | 학습 | ODbL |
| `extra/<출처명>/…/<라벨>/` (Kaggle Cry Sense, Infant cry Dataset 등, 직접 받아서 풀기) | 학습 | 각 데이터 약관 |
| ESC-50 (crying_baby 제외) + OpenSLR 28 등방성 소음 | 소음 증강 | CC BY-NC / Apache 2.0 |
| OpenSLR 28 실측 RIR + 소·중형 방 시뮬레이션 RIR | 잔향 증강 | Apache 2.0 |

원본 버킷은 정제 과정에서 빠진 녹음이라 무음이나 잡음이 섞여 있다. 그래서 YAMNet 울음 점수가 `CRY_MIN`보다 낮은 세그먼트는 버리고, 울음 세그먼트가 하나도 없는 클립은 통째로 제외한다.

## 학습 · 평가

```bash
python train.py                  # 5겹 교차검증 → 최종 모델 학습 → artifacts/
                                 #   클립 50개 이상인 클래스만 자동 선택(--min-clips)
python train.py --classes hungry,discomfort   # 클래스 직접 지정
python train.py --no-pitch       # 피치 증강 제거 비교 (울음 음높이가 이유 단서일 수 있음)
python train.py --holdout-source crysense   # 특정 출처를 학습에서 빼고 일반화 확인
python evaluate.py <라벨폴더>      # 학습에 안 쓴 녹음(예: 직접 녹음)으로 평가
python infer.py a.wav b.wav      # 파일 추론 (인자 없으면 마이크)
```

- **입력 단위 일치**: 학습과 추론 모두 YAMNet 연속 2프레임(≈1.5초) 평균 세그먼트를 쓴다. 실시간 마이크 창 1.5초와 같은 길이다. 클립 판정은 세그먼트 확률의 평균이다.
- **누수 방지**: 같은 아기(앱 설치 UUID)는 한 fold에만 들어간다(StratifiedGroupKFold). 재포장·재인코딩 사본은 파일명 키, 해시, 임베딩 유사도로 같은 group에 묶는다. 조기 종료용 검증셋도 group 단위로 따로 뗀다.
- **기준선 비교**: 최빈 클래스, 로지스틱 회귀, MLP 헤드를 세그먼트 단위와 클립 단위로 비교한다(Macro-F1, Balanced Accuracy, 클래스별 recall).
- **판정 보류**: 최고 확률이 `CONF_MIN`보다 낮으면 `uncertain`으로 둔다. 커버리지와, 판정한 것의 정확도를 함께 보고한다.

산출물(`artifacts/`): `cry_head.keras`, `cry_head.tflite`(온디바이스용 헤드), `labels.json`, `meta.json`, `cv_results.json`, `CV_REPORT.md`, `confusion_matrix.png`

## 결과 (2026-09-24, Donate-a-Cry만 사용)

**데이터**: 정제본 457개 + 원본 버킷 436개(정제본에 없는 녹음) = 893개. 울음 세그먼트가 없는 클립을 빼면 **470개**가 남는다(hungry 397 / discomfort 52 / sleepy 21, 아기 229명).
- 원본 버킷에만 있는 녹음은 YAMNet 울음 점수 중앙값이 0.006이라 대부분 울음이 없다. 같은 녹음의 원본과 정제본을 비교하면 점수가 같게 나오므로(중앙값 0.969 vs 0.948) 변환 문제는 아니다. 애초에 울음이 없어서 정제에서 빠진 녹음이다. 실제로 늘어난 건 52개뿐이다.

**5겹 교차검증, 클립 단위 Macro-F1 (평균 ± 표준편차)**

| 설정 | MLP | 로지스틱 회귀 | 최빈 클래스 | sleepy recall (MLP) |
|---|---:|---:|---:|---:|
| 증강 없음 | 0.298 ± 0.019 | 0.296 ± 0.008 | 0.305 ± 0.021 | 0.00 |
| 증강 2개 (피치 포함) | 0.300 ± 0.040 | 0.308 ± 0.018 | 0.305 ± 0.021 | 0.08 |
| 증강 2개 (피치 제외) | 0.280 ± 0.054 | 0.289 ± 0.014 | 0.305 ± 0.021 | 0.07 |

판정 보류를 적용하면 판정한 클립의 정확도는 0.58~0.79다. 하지만 같은 구간을 전부 hungry로 찍어도 0.83~0.85가 나온다. 즉 모델이 최빈 클래스 추측보다 낫지 않다.

**결론**: 공개 데이터(부모 자가 태깅, sleepy는 21개)로는 3클래스 이유 분류가 **기준선을 넘지 못한다**. 버그를 고치고 평가를 제대로 한 결과이므로, 이것이 현재 데이터의 실제 한계다.

## 추가 결과 (2026-09-26, Kaggle 데이터 검증 + 2클래스)

**Kaggle 데이터 검증**
- Infant cry Dataset은 `cry`/`not_cry` 두 폴더뿐이라 이유 라벨이 없다.
- Cry Sense는 대부분 Donate-a-Cry 재포장본이다.
- Cry Sense의 숫자 이름 파일 532개는 이유 라벨 없는 일반 울음 파일과 바이트 단위로 같고, 같은 파일이 복통·트림·불편·피곤 폴더에 복사돼 있다. 근거 없는 라벨이라 `prepare_data.py`가 제외한다.
- 결과적으로 새로 추가된 건 출처 불명 47개뿐이다.

**2클래스(hungry vs discomfort)**: sleepy는 사용 가능 클립이 27개(아기 19명)라 뺐다.

| 학습 데이터 | 로지스틱 회귀 클립 AUC | Balanced Acc |
|---|---:|---:|
| Donate-a-Cry + Kaggle 47개 | 0.729 ± 0.074 | 0.648 |
| Donate-a-Cry만 (`--holdout-source crysense`) | **0.512 ± 0.095** | 0.472 |

Kaggle 파일이 들어가면 신호가 생기는 것처럼 보이지만, 빼면 무작위 수준이다. 출처 불명 파일이 discomfort에 몰려 있어서(26 : 11) 모델이 울음이 아니라 **데이터 출처를 학습한 지름길**이었다.

**최종 결론**: 공개 데이터로는 2클래스로 줄여도 울음 이유를 학습할 수 없다. 보고서에는 이렇게 적는다. "공개 울음 데이터를 검증한 결과 재포장본과 근거 없는 라벨이 섞여 있었고, 정제된 데이터로는 이유 분류가 기준선 수준이라 채택하지 않았다. 대신 맥락 기반 추정(`cry_context`)을 쓴다."

## 소리 종류 분류 (2026-09-26, 무학습)

울음 이유 대신 **지금 아기방에서 무슨 소리가 나는지**를 나눈다. YAMNet 한 번의 추론이 521개 클래스 점수를 이미 다 내므로, 다른 클래스 점수를 같이 읽기만 하면 된다. 추가 연산이나 추가 모델이 없다(`sound_events.py`).

| 버킷 | YAMNet 클래스 | 시스템에서 쓰는 곳 |
|---|---|---|
| cry 울음 | Baby cry, Crying | 알림·달래기 |
| whimper 칭얼거림 | Whimper | 울기 전 전조 (검증 데이터 없음) |
| laugh 웃음·옹알이 | Baby laughter, Laughter, Giggle, Babbling | "깨서 노는 중", 알림 없음 |
| cough 기침 | Cough, Sneeze, Wheeze | 밤 기침 추세 리포트 |
| other | 그 외 | 무시 |

**판정 규칙**: 울음 점수가 임계값을 넘으면 다른 소리보다 우선해서 울음으로 판정한다. 우는 아기를 "노는 중"으로 보면 알림이 막히기 때문이다. 그 밖의 버킷은 임계값을 넘은 것 중 최고 점수를 고른다. 임계값은 울음·칭얼거림·웃음 0.3, 기침 0.5다.

```bash
python eval_sound_events.py     # → DATA_ROOT/runs/sound_events/SOUND_EVENTS_REPORT.md
```

**평가 결과**: 2,741개 클립. 출처 간 중복 148개는 제외했다. 일부 데이터가 ESC-50을 그대로 가져온 것이었다.

| 버킷 | ROC-AUC | 정밀도 | 재현율 | F1 | 평가 데이터 |
|---|---:|---:|---:|---:|---|
| 울음 | 0.987 | 0.908 | 0.888 | 0.898 | Donate-a-Cry 457 · Infant cry 68 · ESC-50 40 |
| 웃음 | 0.932 | 0.747 | 0.602 | 0.667 | Cry Sense laugh 108 |
| 기침 | 0.985 | 0.723 | 0.850 | 0.782 | ESC-50 기침·재채기 80 (**성인**) |
| 기타 | - | 0.959 | 0.965 | 0.962 | ESC-50 44범주 · 소음·무음 |

4버킷 Macro-F1은 0.827이다. 울음 우선 규칙 없이 최고 점수만 고르면 0.800이다. 울음 우선 규칙으로 울음→웃음 오판은 43건에서 13건으로 줄었다.

**해석과 한계**
- **울음**은 바로 쓸 수 있는 수준이다.
- **기침**의 오경보는 주로 숨소리(18), 물 마시는 소리(8), 코골이(4)에서 나왔다. 아기방에서는 숨소리·코골이가 흔하므로, 기침은 단건 알림이 아니라 **밤 동안의 횟수 추세**로만 쓴다. 성인 기침으로만 평가했다는 점도 한계다.
- **웃음** 폴더는 평균 점수 1위 클래스가 Speech인 클립이 108개 중 56개였다. 데이터 자체에 말소리가 섞여 있어서 수치를 보수적으로 봐야 한다. 성인 웃음 40개 중 21개도 웃음으로 잡혔는데, 보호자가 웃는 소리이므로 돌봄 상황 신호로 해석할 수 있다.
- **고양이 울음 → 울음 오경보**가 12건 있었다. 반려묘가 있는 집에서는 레이더 신호와 교차 확인해 걸러내야 하고, 이게 멀티모달 융합이 필요한 근거가 된다.
- **칭얼거림**은 울음 우선 규칙 때문에 클립 단위에서는 거의 나오지 않는다. 울기 **직전**의 전조로 쓰려면 시간 순서로 따로 평가해야 하고, 그러려면 정답 데이터가 필요하다.
- 모두 근접 녹음 데이터다. 침실 마이크 거리와 잔향에서는 따로 확인해야 한다.

## 연구용 데이터 검증 (2026-09-26)

```bash
python eval_research.py enes    # EnesBabyCries (OSF ru7na): 가정 1~4m 녹음, 아기 24명
python eval_research.py pain    # Corvin 2024 (Zenodo 11061909): 통증 vs 불편, 아기 22명
```
데이터는 `DATA_ROOT/research/`에 둔다. `extra/`에 두면 이유 분류 학습에 자동으로 섞이므로 따로 둔다.

**1. 원거리 울음 감지 (EnesBabyCries, 가정에서 마이크 1~4m)**

| 데이터 | 울음 수 | 1.5초 구간 감지율 | 울음 단위 감지율 |
|---|---:|---:|---:|
| Donate-a-Cry (스마트폰 근접) | 457 | 0.453 | 0.836 |
| EnesBabyCries (가정 1~4m) | 677 | 0.633 | **0.973** |

실제 가정에서 1~4m 떨어져 녹음한 울음도 97%를 감지했다. 나이 회차별로도 차이가 없었다(0.61~0.65). 다만 Enes는 연구진이 울음 음절만 잘라낸 데이터라 사이의 쉼과 배경이 빠져 있다. 그래서 1.5초 구간 감지율은 Donate-a-Cry보다 높게 나오고, 두 수치를 직접 비교할 수는 없다.

**2. 원인 분류 (배고픔 261 / 불편 152 / 혼자 둠 191, 라벨 = 울음을 멈춘 부모 행동)**

| 방법 | 균형 정확도 |
|---|---:|
| 한 아기씩 빼고 학습 (YAMNet + 로지스틱 회귀) | 0.342 |
| + 아기별 평균 제거 | 0.287 |
| 아기별 학습, 다른 나이 회차로 학습 (최근접 평균) | 정확도 0.361 (그 아기의 최빈 원인만 찍으면 0.446) |

무작위는 0.333이다. 논문의 기계 분류 결과(36%)와 같은 수준이다. **아기별로 따로 학습해도 소리만으로는 원인을 알 수 없고, 오히려 "그 아기가 보통 어떤 이유로 우는지"만 찍는 쪽이 더 맞았다.** 소리보다 맥락(시간대, 마지막 수유 이후 경과 시간 등)이 원인을 더 잘 설명한다는 뜻이고, `cry_context`의 방향을 뒷받침한다.

**3. 통증 vs 불편 (Corvin, 불편 = 집에서 목욕 중 196개, 통증 = 병원 예방접종 88개)**

| 입력 | ROC-AUC |
|---|---:|
| 울음 세그먼트 | 0.833 |
| 강한 울음만 | 0.743 |
| **배경만 (울음 점수 0.05 미만 프레임)** | **0.711** |

울음이 없는 배경만으로도 AUC 0.71이 나왔다. 성능의 상당 부분이 **녹음 장소(집 vs 병원)** 에서 온다는 뜻이다. 이 모델을 Enes 가정 녹음에 적용하면 통증이 아닌 울음의 57~72%를 통증으로 판정했고, 집에서 녹음된 통증 울음 4개의 평균 확률(0.41)은 다른 원인(0.53~0.56)보다 오히려 낮았다. **공개 데이터로는 통증 감지를 주장할 수 없다.**

**4. 추가 실험 (`python eval_research.py extra`, EnesBabyCries, 한 아기씩 빼고 학습)**

| 시도 | 3분류 균형 정확도 | 배고픔 vs 나머지 AUC |
|---|---:|---:|
| 소리 (YAMNet) | 0.342 | 0.452 |
| 라벨이 깨끗한 울음만 (부모 판단 = 멈춘 행동, 501개) | 0.298 | - |
| 리듬 (음절 길이·간격·속도) | 0.300 | 0.491 |
| **맥락** (시간대·나이·직전 울음/배고픔 이후 경과 시간·직전 원인) | **0.396** | **0.550** |
| **리듬 + 맥락** | **0.409** | **0.613** |
| 소리 + 리듬 + 맥락 | 0.382 | 0.559 |

라벨을 정리해도, 배고픔 하나로 좁혀도, 소리로는 신호가 없다. 무작위를 넘은 건 맥락 특징뿐이다. 다만 효과가 작고(균형 정확도 0.41), 아기 24명이라 불확실성이 크다. 소리를 더하면 오히려 떨어진다.

**5. 실제 사용 모사 (`python eval_research.py online`)**: 각 아기의 울음을 시간순으로 보며 그 시점 이전 정보만 쓴다. 아기 이력은 이전 울음들의 원인 빈도로, 부모 피드백으로 쌓인다고 가정한다.

| 방법 (이력 10개 이상 쌓인 뒤, 377개) | 3분류 균형 정확도 | 배고픔 AUC |
|---|---:|---:|
| 일반 맥락 모델 | 0.402 | 0.633 |
| 아기 이력만 | 0.413 | 0.585 |
| **맥락 + 아기 이력** | **0.420** | **0.658** |

이력이 쌓일수록 조금씩 오른다(전체 기준 0.416 / 0.633). 지금까지 실험 중 가장 높은 값이고, 제품에서는 "배고픔 가능성" 힌트로 쓸 수 있는 수준이다.

**6. iFLYTEK/Baidu 6클래스 → EnesBabyCries 교차 평가 (`python eval_research.py baidu`)**

Hugging Face에 올라온 2020년 중국 iFLYTEK 울음 대회 데이터 미러(깸·안아줘·배고픔·불편·졸림·기저귀, 학습용 918개)다. 원 대회 약관이 불분명해서 연구 확인용으로만 썼다.

| 평가 | 균형 정확도 | 배고픔 AUC |
|---|---:|---:|
| Baidu 내부 6클래스 (아기 정보 없음) | 0.428 (무작위 0.167) | - |
| └ 유사 중복을 묶어 나눈 경우 | 0.387 | - |
| **Baidu로 학습 → Enes 평가** (아기·환경 완전 분리) | **0.333** (무작위 0.333) | **0.496** |
| Enes로 학습 → Baidu 평가 | 0.354 | 0.546 |

918개 중 517개가 데이터 안에 거의 같은 클립을 갖고 있었다(cos ≥ 0.99). Baidu 안에서는 무작위보다 높게 나오지만, 다른 데이터로 옮기면 정확히 무작위다. 데이터 고유의 녹음 조건 같은 지름길을 배운 것으로 보인다.

**7. IFPaLVD 통증 강도 (`python eval_research.py ifpalvd`, Figshare, CC BY 4.0)**

시술 전후 아기 영상에 임상 통증 점수(FLACC: 없음/중간/심함)와 울음 여부가 붙어 있다. 라벨은 253개 구간인데 **공개 영상은 (아기, 시술 전/후)마다 1개씩 47개뿐**이다.

| 평가 | 결과 |
|---|---|
| 울음 감지 (YAMNet, 울음 vs 비울음) | **AUC 0.946** (실제 병원 영상 소리) |
| 울고 있는 클립 중 심한 vs 중간 통증 (21개, 13:8) | AUC 0.279. 표본이 너무 작아 판단 불가 |
| 같은 비교를 음량·울음 점수만으로 | AUC 0.37~0.58 |

통증 강도는 이 공개분으로는 판단할 수 없다. 나머지 206개 구간을 원저자에게 요청해야 한다. 울음 감지가 다른 환경(병원 영상 녹음)에서도 유지된다는 근거는 하나 더 생겼다.

**결론**: 공개 데이터 4종(Donate-a-Cry, EnesBabyCries, Corvin, iFLYTEK/Baidu)과 선행 연구가 모두 같은 방향을 가리킨다. 울음 소리로 원인을 판별하는 기능은 넣지 않는다. 울음 **감지**는 원거리에서도 유지되고, 원인은 맥락으로 추정한다. 맥락 추정은 실제 데이터에서도 약하지만 무작위보다 나은 신호가 확인됐다.

## 데이터 혼합 + 대형 사전학습 모델 (2026-10-02, GPU 서버)

질문: 데이터를 섞고, 큰 사전학습 오디오 모델을 GPU로 미세조정하면 울음 이유가 잡히는가?

**데이터** (`joint_build.py`, 로컬에서 실행): DAC 470개(울음 있는 원본 포함) + Enes 612개(아기 24명) + Baidu 758개, 총 1,840개 12.6시간.
- 통합 라벨은 hunger / discomfort / isolation(안아주길 원함) / sleepy다. 데이터마다 없는 클래스는 학습·예측에서 마스킹한다.
- 그룹(학습·평가 분리 단위)은 DAC 업로더, Enes 아기, Baidu 유사 중복 묶음이다. Baidu 묶음은 complete linkage, cos ≥ 0.99로 만들었다. union-find로 묶으면 연쇄 때문에 359개짜리 거대 묶음이 생겼다.

**모델** (`joint_train.py`, RTX 4090, 실행은 `joint_run.sh`)
- 동결 6종 + 층 가중합 선형 프로브: AST(AudioSet), CLAP(HTSAT), WavLM-base+, WavLM-large, HuBERT-large, Whisper-small 인코더
- 전체 미세조정 2종: AST, WavLM-base+. 8초 무작위 구간, 음량·잡음 증강, AST에는 SpecAugment, 데이터·클래스 균형 샘플링으로 10 epoch 학습했다.
- 비교 조건 3가지
  - single: 그 데이터만 학습
  - mixed: 세 데이터를 섞어 학습
  - dann: 섞되 출처 판별을 방해(gradient reversal)
- 평가 4가지
  - 그룹 분리 5겹(cv)
  - 데이터 하나를 통째로 빼고 평가(LODO)
  - 겹 분할을 바꿔 5회 반복
  - 데이터 안에서 라벨을 섞은 귀무 분포 5회

**1. 소리만으로 출처(어느 데이터인지)를 99.4~100% 맞힌다.** 섞어서 학습하면 '어느 데이터인가'가 원인보다 훨씬 쉬운 신호가 된다.

**2. Enes (가정 녹음, 아기 분리, 3클래스, 무작위 0.333)**

| 모델 | single | mixed | 배고픔 AUC (mixed) |
|---|---:|---:|---:|
| AST 프로브 | 0.334 | 0.329 | 0.488 |
| CLAP 프로브 | 0.363 | **0.372** | 0.486 |
| WavLM-base+ 프로브 | 0.350 | 0.349 | 0.540 |
| WavLM-large 프로브 | 0.341 | 0.359 | 0.506 |
| HuBERT-large 프로브 | 0.354 | 0.353 | 0.507 |
| Whisper-small 프로브 | 0.361 | 0.339 | 0.503 |
| AST 미세조정 | 0.365 | 0.342 | 0.497 |
| WavLM-base+ 미세조정 | 0.302 | 0.341 | 0.516 |
| *라벨 섞은 귀무 분포 95백분위* | *0.364* | *0.367* | *0.538* |

프로브는 겹 분할 5회 반복 평균이고, 미세조정은 5겹 1회다. 귀무 분포를 넘은 건 프로브 12개 중 CLAP 혼합 하나뿐이고, 이는 우연으로도 기대되는 수준이다. 배고픔 AUC는 모두 귀무 범위 안이다. dann은 오히려 낮았다(AST 0.315, WavLM 0.299).

**3. 섞으면 나아지나 (같은 평가 클립에서 mixed − single)**
- Baidu: 8개 모델·방식 모두 0.02~0.08 떨어졌다. 대부분 구간이 0보다 아래다.
- Enes: −0.03~+0.04, 구간이 모두 0을 포함한다.
- DAC: −0.05~+0.05, 8개 중 CLAP 하나만 +0.053으로 0을 벗어났다.
- 일관된 이득은 없다.

**4. 다른 데이터로 옮기기 (LODO)**: 균형 정확도가 전부 무작위 수준이다(Enes 0.33~0.34, DAC 0.26~0.35, Baidu 0.22~0.29). 예외는 DAC+Enes로 학습해 Baidu의 배고픔을 맞히는 경우로, AUC 0.57~0.60이 나왔다(CLAP·HuBERT·WavLM-large 프로브).

**5. Baidu 안에서는 높게 나온다**: 프로브 0.50~0.60, AST 미세조정 0.607(무작위 0.25), 배고픔 AUC 0.70~0.75다. 하지만 아기 정보가 없어 같은 아기가 학습과 평가에 섞였을 수 있고, 다른 데이터로는 전혀 옮겨지지 않는다. 녹음 세션 지름길로 본다. DAC도 CLAP·AST 프로브의 배고픔 AUC가 0.60으로 귀무 분포(95% 0.53~0.56)를 조금 넘는다. 다만 자가 태깅이고 배고픔이 85%라 쓰기 어렵다.

**6. 소리 확률을 맥락 + 아기 이력에 더하기** (`python eval_research.py online_audio`)
- 기존 최고(맥락 + 이력)는 전체 0.416, 배고픔 AUC 0.633이다.
- 대형 모델 소리 확률 17종(아기 분리 예측)을 하나씩 더해 봤다. 변화는 −0.026~+0.002이고, 모두 아기 단위 부트스트랩 구간이 0을 포함한다.
- 소리를 더해도 나아지지 않는다.

**결론**: 데이터를 섞고 대형 모델을 미세조정해도, 울음 소리로 원인을 일반화하지 못한다. 출처가 원인보다 훨씬 쉬운 신호라서 섞으면 오히려 떨어진다. 제품 경로는 그대로 간다. 울음은 감지하고, 원인은 맥락과 아기 이력으로 '배고픔 가능성' 힌트만 준다.

실행 순서
```bash
python joint_build.py          # 로컬: DATA_ROOT/joint/ (16kHz wav + meta.csv)
# GPU 서버의 ~/cry/data/joint 로 복사한 뒤 (joint_train.py, joint_run.sh 는 ~/cry)
setsid nohup ./joint_run.sh > joint_run.log 2>&1 < /dev/null &
```
`joint_run.sh` 실행 순서
1. `.bin` 가중치를 safetensors로 변환
2. 겹 배정
3. 6종 프로브와 반복 검증
4. AST·WavLM 미세조정
5. 보고서 작성

다른 사람이 GPU를 쓰는 중이면 빌 때까지 기다린다. torch 2.5와 transformers 5.x 조합에서는 `.bin` 로드가 막혀 있어서(CVE-2025-32434) 변환 단계가 필요하다. 결과는 `runs/JOINT_REPORT.md`에 저장되고, 로컬 사본은 DATA_ROOT/runs/joint/에 있다.

## 2차: 데이터 확장 + 연구 기반 기법 (2026-10-02, GPU 서버, 일부 진행 중)

1차에서 빠졌던 데이터와 관련 연구(Bonafos 2025, Wu 2026, Ubenwa 2023, voc2vec)에서 제안한 기법을 더했다.
실행은 `joint_run_v2.sh`이고, 데이터는 `joint_build.py`가 만든 joint2(라벨 2,124개·라벨 없는 울음 462개·증강 묶음)다.

**데이터 점검에서 나온 것**
- Kaggle Cry Sense '출처 불명' 47개 중 37개가 DAC 클립의 재인코딩본이었다(voc2vec 유사도 ≈ 1.0, 라벨 92% 일치).
  - 이전의 파일명·md5 검사로는 잡히지 않았다. 1차의 'Kaggle 47개를 넣으면 AUC 0.73'도 이 누수였다.
  - 섞으면 DAC가 0.33에서 0.47로, Cry Sense가 0.85로 부풀었다. 그래서 뺐다.
- Infant cry Dataset 울음 565개 중 458개도 DAC와 같은 소리였다. 라벨 없는 울음 묶음에서 뺐다.
- 데이터 사이의 다른 중복은 없었다(voc2vec 유사도 0.98 이상 0개).

**① 아기별 정규화**: 같은 아기(그룹)의 라벨 없는 울음 평균을 빼서 '누구 울음인지' 성분을 지웠다(모델 6종, 5회 반복).

| | 아기 식별 정확도 (Enes) | Enes 원인 균형 정확도 | 배고픔 AUC |
|---|---:|---:|---:|
| 정규화 없음 | 67~81% (데이터셋 평균만 뺐을 때) | 0.33~0.37 | 0.47~0.54 |
| 아기별 정규화 | 0.2~0.8% | 0.32~0.38 | 0.45~0.55 |
| 시간순(그 아기의 이전 울음 평균만) | 14~24% | 0.30~0.38 | 0.46~0.54 |
| *무작위 라벨 95백분위* | | *0.36~0.37* | *0.54~0.55* |

- 신원 정보는 거의 다 지워졌지만 원인 신호는 드러나지 않았다.
- 덤으로, DAC에서 보이던 배고픔 AUC 0.60(CLAP·AST·Whisper)이 업로더별 정규화 뒤 0.5로 사라졌다. 업로더(기기·가정) 지름길이었다.

**② 울음·발성 특화 모델** (동결, 층 가중합 프로브, 5회 반복): voc2vec(아기 울음 포함 비언어 발성 125시간), voc2vec-HuBERT, wav2vec2-large·UniSpeech-large(Bonafos 2025 계열)를 1차 6종과 비교했다(11종).
- Enes 원인: 11종 모두 0.32~0.38이다(voc2vec 0.34~0.36, voc2vec-HuBERT 0.34~0.37, wav2vec2-large 0.35~0.36, UniSpeech-large 0.33~0.36). 무작위 라벨 95백분위(0.37)와 같다.
- 섞기(mixed) vs 단일(single): 일관된 차이가 없다.

**④ 울음 도메인 추가 사전학습(DAPT)**: voc2vec(wav2vec2)을 라벨 없는 울음과 Enes 외 데이터 소리 6.5시간(1,909개)으로 6,000스텝 더 학습했다. Enes 라벨 울음은 빼서 Enes 평가는 '처음 듣는 소리' 조건을 지켰다.
- 대조 손실은 3.15에서 3.12로 줄었다.
- Enes 원인은 0.35로 그대로였다. 데이터가 6.5시간뿐이라 Ubenwa(병원 신생아 1,000명 이상)·Cry2Vec(300만 클립) 규모와는 거리가 멀다.
- CryCeleb(6.5시간)은 Hugging Face 약관 동의가 필요해 아직 넣지 않았다.

**Corvin 통증 vs 불편 (통증 클래스 후보)**: 프로브 AUC가 0.86~0.95로 높았다. 그래서 같은 모델로 한 클립을 세 가지 입력으로 나눠 비교했다(`joint_train.py background`).

| 입력 | WavLM-large | AST | voc2vec |
|---|---:|---:|---:|
| 전체 | 0.941 | 0.928 | 0.865 |
| 큰 소리 구간(울음) | 0.821 | 0.844 | 0.758 |
| 조용한 구간(울음 사이 배경) | **0.901** | **0.855** | **0.800** |

울음이 거의 없는 조용한 구간만으로도 울음 구간과 같거나 더 잘 맞힌다. 통증(병원 예방접종)과 불편(집 목욕)의 녹음 장소 차이를 배운 것이어서, 이 데이터로 통증 클래스를 만들 수 없다(1차 YAMNet 배경 AUC 0.71과 같은 결론).

**⑤ 시간 구조 모델, ③ 안정화 미세조정**: 학습 도중 GPU 서버가 멈춰 결과를 받지 못했다(2026-10-02 16:37경 멈춤, 17:17 재부팅). 커널 로그가 끊겨 원인(GPU 오류·메모리)을 확정하지 못했다. 직전에 CUDA 'unspecified launch failure'가 세 번 났고, 미세조정·시간 구조 모델·프로브를 병렬로 돌리던 중이었다.
- ⑤ 시간 구조 모델: 4초 창 순서를 보는 트랜스포머 vs 창 평균, 3시드
- ③ 안정화 미세조정: voc2vec·voc2vec_dapt, 실측 잔향·잡음 증강, 층 가중합, lr 1e-5, 아기 구분 방해(badv)
- 서버가 복구되면 `joint_run_v2.sh`를 다시 돌린다(끝난 단계는 건너뛴다). 메모리·GPU 부담을 줄이려면 병렬 작업 수를 줄여야 한다.

## 시스템 연동 상태

실시간 경로(`../cry_classifier.py`)는 지금 울음 **유무**만 판정하고 `cls="none"`을 발행한다. 이유 분류를 붙이려면 두 가지가 필요하다.
1. 파이의 YAMNet tflite가 **임베딩을 출력**하는지 확인해야 한다. 점수만 나오는 분류용 tflite라면 SavedModel에서 임베딩 출력판을 다시 변환한다.

## 한계 (보고서 표현 주의)

- 라벨은 부모가 앱에서 직접 고른 자가 태깅이라 잡음이 크다. 정답 자체가 불확실하다.
- 공개 데이터는 스마트폰 근접 녹음이다. 침실 마이크 환경과의 차이는 증강으로 일부만 보완된다.
- 이유 분류는 **실험적 힌트**다. 실사용에서는 맥락(`../cry_context.py`)과 함께 보여주고, "울음 이유를 판별한다"고 주장하지 않는다.
