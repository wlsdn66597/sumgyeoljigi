# 울음 원인 분석과 시뮬레이션 정리

기준일 2026-10-19. 실험별 상세 수치와 명령은 `cry_model/README.md`(1~13차)에 있다. 이 문서는 흐름과 결론, 지금 기본값, 발표 때 주의점을 정리한다.

## 1. 한 줄 요약

공개 데이터로 미리 학습한 모델은 **처음 듣는 아기의 울음 원인을 맞히지 못한다**(1~5차, 무작위 수준). 그래서 **그 아기의 부모 답을 쌓아 배우는 1·2순위 행동 힌트**로 방향을 바꿨고, 가상 시뮬레이션으로 이 구조가 실제로 배운다는 것을 확인했다.

- 가상 세계(8가지 정답 규칙 평균) 기준 1순위 0.61, 정답이 1·2순위 안에 들 확률 0.88이다. 무작위로 찍으면 0.33 / 0.67이다.
- 답이 20개쯤 쌓이면 크게 오르고, 80개 이후에는 거의 평평하다.

## 2. 실제 데이터에서 확인한 것 (1~6차)

| 차수 | 내용 | 결과 |
|---|---|---|
| 1~2차 | 공개 데이터 통합(DAC·Baidu·Enes·Corvin 등), 대형 모델 11종(AST·CLAP·WavLM·HuBERT 등), 미세조정, 증강, 울음 추가 사전학습 | 처음 듣는 아기 대상은 모두 무작위(0.32~0.38). 좋아 보이던 점수는 지름길이었다(업로더 차이, 녹음 장소, 재포장 중복 파일) |
| 3~4차 | Enes(가정 녹음, 아기 24명, 울음을 멈추게 한 행동 라벨) 재구성, 아기별 개인화 | 그 아기의 이전 울음과 비교하면 귀무를 넘었다(0.43~0.47 vs 0.37~0.38). 처음으로 확인된 약한 소리 신호다 |
| 5차 | openSMILE(ComParE·eGeMAPS, ChatterBaby 방식) | 추가 이득 없음 |
| 6차 | 파이 모듈 그대로 시간순 재생 | 맥락(마지막 수유 후 시간 등) + 이력 0.456, 배고픔 AUC 0.62. 소리를 섞으면 오히려 떨어짐 |

실제 라벨에서 쓸 만한 신호는 맥락 + 이력뿐이고, 그것도 귀무(0.446)를 겨우 넘는다. **실제 원인 정확도를 주장할 근거는 없다.**

## 3. 가상 시뮬레이션 (7~13차)

### 설계
- 실제 울음 소리(Enes 아기 22~24명 + 공개 데이터, 총 2,521개)에 **가상의 부모 답(행동 라벨)**을 붙인다. 아기마다 울음을 소리 특징으로 3유형으로 나누고, 유형마다 행동(수유 / 기저귀 / 안아주기)을 아기마다 다르게 짝짓는다.
- 파이 모듈(`cry_personal.py`)에 시간순으로 넣는다. 울음마다 그때까지 쌓인 답으로 **먼저 맞히고**, 그다음 답을 받는다. 미래 정보는 쓰지 않는다.
- 정답 규칙을 만든 특징과 비교에 쓰는 특징이 같으면 시험이 그 방법에 유리해진다(순환). 그래서 **정답 세계를 8가지로 만들어 평균을 낸다.**
  - 요약 6 / eGeMAPS / MFCC / YAMNet / 스펙트럼 모양 / 리듬 / 목소리 / 혼합(모든 특징을 무작위 비율로 섞음)
- 표본을 키우려고 Enes 아기 4명 또는 11명을 이어 붙였다. 아기마다 평균을 빼 목소리 차이를 지우고 시간 순서를 지킨다. 가상 아기 하나가 울음 약 100개 또는 275개가 된다.

### 차수별 흐름
| 차수 | 시도 | 결과 → 결정 |
|---|---|---|
| 7 | 가상 라벨 기능 시험 | 신호가 없으면 무작위 유지, 아기마다 규칙이 다르면 일반 모델은 실패하고 개인화만 배움 |
| 8 | 증강, YAMNet → 음향 특징 변환 | 증강은 같은 방에선 효과 없고 조건이 바뀔 때만 이득. 음향 변환 공간이 YAMNet보다 낫다 |
| 9 | 비교 공간 공정 비교(정답 4세계) | YAMNet 16차원 0.45 → 음향 변환 0.53~0.60 → 채택. 자가 검증 도입 |
| 10 | 행동 3·4·6개, 파이용 MFCC(numpy, librosa와 동일) | MFCC +0.02~0.04 → 채택. 행동을 늘리면 1순위는 내려가고 무작위 대비 이득은 비슷 → **행동 3개 + 1·2순위 표시로 확정** |
| 10+ | 긴 사용 기간(울음 100·275개) | 답 20개 전후 급상승, 80개 이후 평평 |
| 11 | 아기별 판별 분석, '아니었어요' 답, 답 없는 울음 활용 | 블록이 적을 땐 효과 0~0.02. 가장 큰 변수는 부모 답 비율(100% → 50%면 초반 0.53 → 0.47) |
| 12 | 리듬 특징 8개, 아기별 맥락 | 리듬: 리듬 세계 +0.06~0.14(200번째 이후까지 유지) → 채택. 아기별 맥락은 실제 데이터에서 손해 → 미채택 |
| 13 | 목소리 질 14개(numpy YIN), 스펙트럼 20개, 블록 합치기 | 전체 평균 0.579 → **0.612** (1순위), 0.862 → 0.877 (2순위 안). 블록이 6개가 되자 아기별 판별 분석이 처음으로 효과 → **기본값** |

강화학습(PPO 등)은 쓰지 않는다. 울음 하나가 '추천 → 결과'로 끝나는 한 단계 문제이고, 부모가 정답을 알려 주며, 아기당 시행이 수십~수백 번뿐이기 때문이다.

### 지금 기본값의 점수 (13차, 가상 아기 울음 약 100개, 소리 항상 켬)

| 비교 공간 | 목소리 세계 | 혼합 세계 | 전체 평균 (8세계) | 울음 80번째 이후 |
|---|---:|---:|---:|---:|
| 이력만 | 0.33 / 0.66 | 0.33 / 0.66 | 0.343 / 0.675 | 0.35 / 0.69 |
| 이전 (음향+MFCC+리듬) | 0.45 / 0.77 | 0.58 / 0.87 | 0.579 / 0.862 | 0.61 / 0.88 |
| **지금 (블록 6개 + 아기별 판별 분석)** | **0.68 / 0.91** | **0.61 / 0.88** | **0.612 / 0.877** | **0.65 / 0.90** |

칸 = 1순위 균형 정확도 / 정답이 1·2순위 안에 든 비율.

### 답이 쌓이는 속도 (행동 3개, 자가 검증 켬, 울음 약 275개)

| 쌓인 답 | 10~19 | 20~39 | 40~79 | 80~119 | 160~199 | 200 이상 |
|---|---:|---:|---:|---:|---:|---:|
| 1순위 / 2순위 안 | 0.36 / 0.66 | 0.48 / 0.78 | 0.49 / 0.78 | 0.51 / 0.81 | 0.55 / 0.83 | 0.54 / 0.82 |

(10~12차 기본값 기준. 13차 기본값으로 긴 기간을 다시 재는 것은 남은 작업이다.)

## 4. 파이 모듈 기본값 (`cry_personal.py`)

| 항목 | 값 |
|---|---|
| 행동 | 3개(수유 / 기저귀 / 안아주기), 1·2순위 함께 표시(`top2`, `show2`: 답 10개부터) |
| 힌트 | 맥락 × 이력(최근 답 가중) × 소리 |
| 소리 비교 공간 | 블록 6개 232차원: YAMNet 16, 음향 변환 134(YAMNet → 음높이·크기·eGeMAPS·MFCC 선형), MFCC 40, 리듬 8, 목소리 질 14, 스펙트럼 20 |
| 비교 방법 | 아기별 판별 분석(`sound_method="lda"`, 답이 적을수록 단순 거리 비교 쪽으로 축소) |
| 자가 검증 | 답 5개부터 '소리 포함/제외' 예측을 몰래 기록, 최근 20개 중 소리 포함이 2개 이상 더 맞을 때만 소리 사용 |
| 부분 답 | '해 봤는데 안 그쳤어요'(`feedback_not`) 사용 |
| 저장 | 울음마다 원 임베딩·소리 통계 82개 저장 → 변환이 바뀌어도 부모 답 재사용 |
| 비용 | 1초 창당 약 18ms(노트북), 울음당 상태 약 9~10KB |
| 필요 파일 | `cry_model/artifacts/`: yamnet_emb.tflite, cry_personal_acoustic.npz, cry_personal_basis.npz, cry_personal_ctx.json (git 제외, 재생성: `sim_kclass.py feats` → `export`, 노트북 12분) |

## 5. 남은 작업
1. 파이 실시간 경로 연결: 임베디드 YAMNet 출력에서 임베딩·1초 소리 전달 → 울음 구간 추적 → 10초 힌트 발행(`cry/hint`) → 부모 답(`cry/feedback`)
2. 파이에서 처리 시간 측정
3. 자가 검증을 시연에서 켤지 결정. 끄면 가상 점수 초반 +0.02~0.05, 켜면 실제 데이터에서 손해가 없다(실제 Enes: 항상 켬 0.377 vs 자가 검증 0.421, 이력만 0.433)
4. 13차 기본값으로 긴 기간(울음 275개) 재측정, 보고서용 학습 곡선 그림 — GPU 서버 필요(10-17부터 오프라인)
5. atlas(C++) 쪽으로 옮길지, 일반 파이(Python)에 둘지 결정

## 6. 발표·보고서에서 주의할 점
- "울음 의도를 분류한다"고 쓰지 않는다. **"아기별로 쓸수록 맞춰지는 1·2순위 대응 힌트"**로 쓴다.
- 수치는 반드시 **가상 시뮬레이션 기준**임과 **무작위 기준선(0.33 / 0.67)**을 함께 밝힌다. 2순위 안 적중률은 무작위로도 67%다.
- 가상 세계는 "원인이 그 아기의 울음 소리에 드러난다"는 가정이다. 이 시뮬레이션이 보여주는 것은 **패턴이 있으면 시스템이 배운다**는 기능 검증이지, 실제 울음에 그 패턴이 있다는 증명이 아니다.
- 실제 데이터(Enes)에서 소리는 우연 수준이고, 자가 검증이 이를 감지해 소리를 거의 끈다. 이것을 안전장치로 설명할 수 있다.
- 의료기기가 아니다. 통증·질환 판단을 주장하지 않는다.
